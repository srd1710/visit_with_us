# Visit with Us — Wellness Tourism Purchase Prediction

End-to-end MLOps project using **GitHub Actions** for dataset validation, preprocessing, model tuning/training and model versioning, plus **Streamlit Community Cloud** for the prediction app. No Hugging Face or Codespaces required.

## Repository structure

## 1. Push this project to GitHub

1. Create a GitHub repository and use the `main` branch.
2. Upload/push the complete contents of this project, including `.github/workflows/pipeline.yml` and `tourism_project/data/tourism.csv`.
3. In **Settings → Actions → General → Workflow permissions**, allow read and write permissions if your organization policy requires this. The workflow also declares `contents: write`.
4. The workflow runs automatically on a push to `main`, or start it manually from **Actions → Tourism Project Pipeline → Run workflow**.

The workflow does not need a PAT secret: GitHub's built-in `GITHUB_TOKEN` is used by `actions/checkout` and the job's `contents: write` permission to commit the model. Keep tokens out of source code.

## 2. Pipeline stages

1. **Register dataset:** validates required columns, binary target and prints a data summary.
2. **Prepare data:** drops identifier/index columns (`CustomerID`, `Unnamed: 0`), separates `ProdTaken`, and creates stratified 80/20 train/test splits.
3. **Train and evaluate:** imputes missing values, scales numeric columns, one-hot encodes categorical columns, tunes an XGBoost classifier using cross-validation, and reports accuracy, precision, recall, F1 and ROC-AUC.
4. **Track and register:** records parameters and metrics with MLflow; saves `model.joblib` and `model_metadata.json` into `tourism_project/deployment/`; commits those files back to `main`.

The model-training job uploads its MLflow run directory as a GitHub Actions artifact. The CI run uses a local MLflow file store; it does not publish a remotely accessible MLflow UI. For local experimentation with an ngrok tunnel, see below.

## 3. Deploy Streamlit

After the GitHub Actions workflow completes successfully and the model files are committed:

1. Open [Streamlit Community Cloud](https://share.streamlit.io/) and sign in with the GitHub account that can access the repository.
2. Create an app and select your repository and `main` branch.
3. Set **Main file path** to `tourism_project/deployment/app.py`.
4. In Advanced settings, select Python **3.11**.
5. Deploy. Streamlit installs `tourism_project/deployment/requirements.txt`.

If the app reports that the model is missing, the training workflow has not completed or the generated model files have not been committed yet.

## 4. Run locally

Use Python 3.11:

```bash
python -m venv .venv
# Windows:
.venv\\Scripts\\activate
# macOS/Linux:
source .venv/bin/activate

python -m pip install -r tourism_project/requirements.txt
python tourism_project/model_building/data_register.py
python tourism_project/model_building/prep.py
python tourism_project/model_building/train.py
streamlit run tourism_project/deployment/app.py
```

## 5. Optional MLflow + ngrok experimentation

The GitHub Actions workflow logs to a local MLflow file store and uploads it as an artifact. For an interactive MLflow UI during a local/Colab experiment, install `pyngrok`, set your ngrok token as an environment secret, and run:

```python
import os
from pyngrok import ngrok

# Set NGROK_AUTHTOKEN in your environment/Colab secret store; do not hardcode it.
ngrok.set_auth_token(os.environ["NGROK_AUTHTOKEN"])
os.system("mlflow ui --host 0.0.0.0 --port 5000 > mlflow.log 2>&1 &")
public_url = ngrok.connect(5000, "http").public_url
print("MLflow UI:", public_url)
```

Then set `MLFLOW_TRACKING_URI` to the returned URL before running `train.py`. This tunnel is optional and is not required by GitHub Actions or Streamlit deployment.

## Notes

- The supplied CSV has 4,128 rows and 21 columns. The project drops `CustomerID` and the exported index column `Unnamed: 0` from model features.
- `ProdTaken` is the prediction target (0 = did not purchase, 1 = purchased).
- Model probabilities are estimates and should be validated against campaign outcomes before operational use.
- Do not commit GitHub PATs, ngrok tokens, or other credentials.
